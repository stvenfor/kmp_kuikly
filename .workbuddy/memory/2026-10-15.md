### 关键发现（非常重要）
- **`compileKotlinMetadata` 在本工程对所有模块都是 SKIPPED**（连已知良好的 feature-feed 也如此），不是真实编译任务。**不能作为编译判定**。
- 真实编译/验收路径：
  - UI 页：`env -u HTTP_PROXY ... ./gradlew :app-shared:compileDebugKotlinAndroid`（app-shared 通过 `kotlin.srcDir` 聚合各 feature 的 `src/pages/kotlin`）。
  - 单测：`feature-x` 依赖的 `core-data/core-navigation` **无 jvm 变体**，故不能加 `jvm()` 目标 + `jvmTest`（会 Gradle 变体匹配失败）。应走 `:feature-x:testDebugUnitTest`（Android 单元测试）。
- JAVA_HOME 必须指向 `/Library/Java/JavaVirtualMachines/jdk-17.jdk/Contents/Home`（原 `/usr/local/opt/openjdk@17` 已失效）。编译前 `export JAVA_HOME=...` 并 `env -u HTTP_PROXY -u HTTPS_PROXY ...` 直连（规避 127.0.0.1:7897 代理残留）。
- Kuikly Compose 文档未暴露 Canvas API → 图表用基础组件（Box/Column/Row/Modifier）组合近似还原（转化环/迷你柱/漏斗/雷达），零 Canvas 依赖。
- Gradle 首次构建会下载 gradle-8.5 + 全部依赖，约 4-5 分钟；之后增量快。

### Kuikly Compose 编译踩坑（已确认，务必遵守）
- `@Composable` 来自 **`androidx.compose.runtime.Composable`**（不是 compose.* 新包）。
- **`fillMaxHeight()` 不可用** → 用 `fillMaxSize()` 替代。
- **`Modifier.weight()` 本项目无先例/有风险** → 列表行布局避免用 Row+weight，改用纯 Column 堆叠。
- `MockScenario` / `MockBackend` 都在包 **`com.example.kuikly.data.mock`**（不是 `com.example.kuikly.data`）。
- feature 模块两层结构：`src/commonMain`(数据/逻辑) + `src/pages/kotlin`(页面，被 app-shared 的 srcDir 聚合后经 KSP 识别 @Page)。
- Kotlin 字面量类型敏感：`Product(price=Double)` 传 `1500` 会 "Argument type mismatch: actual Int, expected Double"，必须写 `1500.0`。
